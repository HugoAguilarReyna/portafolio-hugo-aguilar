# MongoDB M5 en el VPS

Usar desde `/opt/portafolio`, con los repositorios `portfolio-api` y
`portafolio-hugo-aguilar` como directorios hermanos:

```bash
bash portafolio-hugo-aguilar/deploy/compose-con-m5.sh config --quiet
bash portafolio-hugo-aguilar/deploy/compose-con-m5.sh up -d --wait mongo-m5
```

El comando incorpora `config-local/gaza-memoria.yml` si existe. Usarlo en las
actualizaciones siguientes para conservar tanto Gaza como la conexión de M5.
MongoDB 8.0 conserva los datos en el volumen `portafolio_m5_datos`. No publica
puertos del host y se comunica con la API por una red interna exclusiva.

Restaurar únicamente el respaldo de `atlas_comercial_local` previamente
verificado con SHA-256. La restauración no incluye `--drop`: detenerse y revisar
si ya hay colecciones; no sobrescribir una base existente sin revisarla.

```bash
bash portafolio-hugo-aguilar/deploy/compose-con-m5.sh exec -T mongo-m5 \
  mongorestore --gzip --archive --stopOnError \
  --nsInclude='atlas_comercial_local.*' < m5-vps-20261122.archive.gz
```

Después de restaurar, construir la API actualizada y recrear API y web. La
recreación de nginx hace que resuelva la dirección del nuevo contenedor API.

```bash
bash portafolio-hugo-aguilar/deploy/compose-con-m5.sh build api
bash portafolio-hugo-aguilar/deploy/compose-con-m5.sh up -d --no-build \
  --no-deps --force-recreate --wait --wait-timeout 180 api web
curl -fsS http://127.0.0.1:8080/api/v1/comercial/m5/estado
```

La salud general de la API no sustituye la comprobación de `/comercial/m5/estado`
y las consultas del tablero. No ejecutar `down --volumes`: eliminaría datos
persistentes. El respaldo conserva los resultados originales; no reentrena ni
crea una nueva evaluación independiente del modelo.
